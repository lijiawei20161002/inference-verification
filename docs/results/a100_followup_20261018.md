# A100 follow-up results, 18 October 2026

[Experiment map](../../experiments/README.md) · [Archived evidence](a100_followup_20261018/) ·
[Verified numerical summary](a100_followup_20261018/summary.json)

**The A100 phase completed:** one frozen honest capture, four verifier replay
schedules with an exact same-shape control, and two clean timing measurements.
The capture contains 80 distinct prompt token sequences and 20,480 generated
positions. Paired H100/A100 replay remains open because only the A100 was
available in this session. These runs do not measure deployment false-positive
rates or attack power.

| Measurement | Coverage | Process wall time |

All same-shape scores matched exactly for all four detectors. A separate
4-prompt × 16-position smoke capture was replayed in two processes; all scores
matched exactly across all four schedules. The existing 151 tests passed before
implementation; the full suite including 13 new capture/pairing checks passed
164 tests. Two pre-existing warnings concern a service dependency deprecation
and a test that intentionally exceeds the batch/pool ceiling.

The first full context-window run overlapped CPU tests. It is retained as
`clock-window-preliminary.json` and excluded from the headline timing comparison.
The reported stability and clean window runs followed the tests and ran serially.
The final checker verifies hashes, complete timing grids, sample counts, rounded
and unrounded means, raw rerun equality, and every reported bootstrap interval.

## Honest frozen-token replay

Qwen3-1.7B BF16, eager sequential generation, the first 80 built-in prompts
with input length capped at 32 tokens, temperature 1, top-k 50, top-p 0.95,
shared seed 42. Both synthetic logit noise and activation noise are disabled.
Exact prompt IDs, input token IDs, output token IDs, sampling parameters, and
32-dimensional projected activation fingerprints were serialized once. Replay
reads those saved IDs directly without retokenizing or regenerating output.

The baseline is batch-1 eager full-sequence reference replay. Positive d′ means
the alternate schedule raises the anomaly score. Scores are winsorized at the
baseline 99.9th percentile, then the mean difference is divided by baseline
standard deviation. Intervals use 400 paired sequence bootstrap draws, seed 0,
with the 5th and 95th percentiles. Token positions are not independent bootstrap
units. These are exploratory per-comparison intervals, not simultaneous bounds.

All twelve effect sizes, intervals, and other saved aggregate statistics exactly
match the [17 October A100 artifact](a100_campaign_20261017/token-shape.json),
despite the host/driver change. This is an aggregate replication on the same GPU
SKU; the earlier archive has no per-sequence scores or frozen capture with which
to establish row-by-row equivalence. Batch and SDPA intervals for the three token
detectors include zero. Sequential replay shifts their scores downward.

## Context timing and repeatability

The observations are local host-clock intervals with CUDA synchronization,
including measurement overhead. They are not client network arrivals or pure
kernel timings. The CUDA-graph path uses a static KV cache, batch 1, and untimed
256-token prefill chunks. The repeated-text fixture varies effective input/cache
length; it does not serve identical long requests through a truncating endpoint.

| Effective context | Mean decode interval, ms | Difference from 256 tokens, ms |
|---:|---:|---:|
| 256 | 7.460 | 0.000 |
| 512 | 7.910 | 0.450 |
| 2,048 | 10.952 | 3.492 |
| 8,192 | 22.660 | 15.200 |
| 16,384 | 38.157 | 30.697 |
| 32,768 | 69.203 | 61.743 |

The clean window gap is **61.743 ms**. The separate stability
process measured **61.765 ms**; across the four shared
contexts, mean intervals differ by at most **0.01210 ms**.
This is short-term repeatability of this local fixture. The 17 October campaign
reported a 61.863 ms window gap, but the new run uses another host and driver
570.133.20 instead of 595.91.07. Their difference cannot be attributed solely to
elapsed time, GPU SKU, or any single system variable.

## Provenance and reproduction

Node `a100-80-02`, NVIDIA A100-SXM4-80GB, Python 3.12.3, PyTorch 2.8.0+cu128,
Transformers 4.57.6, NumPy 2.1.2, Accelerate 1.15.0. CPU thread settings were
`OMP_NUM_THREADS=1` and `OPENBLAS_NUM_THREADS=1`. The model and tokenizer use
revision `70d244cc86ccca08cf5af4e1e306ecf908b1ad5e` and offline loading.

Timing runs used clean commit `9092f324c1c04aa1a3dcf6ac20417455a86ca450` through
`scripts/run_research_job.py`. Frozen capture/replay used a separate checkout of
that base plus the new `exp_frozen_replay_gpu.py`; its manifest records SHA-256
for every relevant source file. The source archive is retained locally at
`runs/frozen-source.tar.gz`; overlay it on a checkout of the base commit when
reconstructing the run. The archive omits `.git`, model weights and credentials.
Package and NVIDIA snapshots are included in the result archive.

From the repository root, rebuild and check the numerical summary without a GPU:

To finish the paired experiment, copy the frozen capture and A100 replay

`runs/frozen-20261018/replay_h100.sh`. The general capture/replay commands are in
the [experiment map](../../experiments/README.md#frozen-capture-and-paired-gpu-replay).

runtimes, numerical flags, score hashes, or failed controls. Driver differences
are recorded and must be interpreted together with hardware differences.
