honest token scores slightly downward. Paired H100/A100 replay and deployment
false-positive calibration remain open.

## Honest token replay

Source: [token-shape.json](a100_campaign_20261017/token-shape.json).
One honest Qwen3-1.7B BF16 pool was replayed under four verifier schedules.
The baseline is batch-1 eager prefill; alternative schedules change batching,
attention implementation, or KV-cache replay. Only the **clean** arm ran,
with injected logit and activation noise disabled. Sampling used temperature
1, top-k 50, top-p 0.95, seed 42, and 80 built-in prompts capped at 32 prompt
tokens, each generating 256 positions.

| Verifier change | token_difr d′ | 90% paired sequence-bootstrap interval |
|---|---:|---|
| Batch 4 with unrelated filler rows | −0.00679 | [−0.01691, +0.00363] |
| SDPA attention | −0.00660 | [−0.01473, +0.00345] |
| Sequential KV-cache replay | −0.03164 | [−0.03996, −0.02255] |

The statistic is the change in mean score divided by baseline score standard
deviation, with winsorization at the baseline 99.9th percentile. Intervals use
400 paired sequence-bootstrap resamples. The same-shape rerun has exactly
zero d′ and zero changed scores for all four detectors.

Batch and SDPA intervals include zero. Sequential replay has a small negative
shift, away from this detector's high-score alarm direction, while still
changing the honest distribution. Sequential `activation_difr` changes by
−1.46284 d′; that detector needs internal activations and is an additional
visibility control. The artifact's `frac_tokens_changed` means changed
**scores at token positions**: all replay comparisons use the same tokens.

No attack was generated and no held-out FPR or attack power was measured here.
The artifact's `reference_dprimes` and `price_of_the_floor` use historical
simulated/noisy attack results; they are not new A100 detection or cost results.

## Context timing and short-term repeatability

Source: [clock-window.json](a100_campaign_20261017/clock-window.json).
Qwen3-1.7B BF16, batch 1, CUDA graph with static KV cache, 192 decode steps
× 4 repetitions per setting. Observations use the **host clock plus CUDA
synchronization**, including measurement overhead. They are local decode
intervals, not client network arrival times or pure kernel timings.

| Effective context | Mean decode interval, ms | Difference from 256 tokens, ms |
|---:|---:|---:|
| 256 | 7.377 | 0.000 |
| 512 | 7.819 | 0.442 |
| 2,048 | 10.875 | 3.498 |
| 8,192 | 22.604 | 15.227 |
| 16,384 | 38.130 | 30.752 |
| 32,768 | 69.240 | 61.863 |

The immediately following
[stability run](a100_campaign_20261017/clock-stability.json) measured contexts
256, 1,024, 4,096, 8,192, 16,384 and 32,768, with a full-minus-short gap of
**61.848 ms**. At the four shared contexts (256, 8,192, 16,384 and 32,768),
mean intervals differed by at most **0.02124 ms**. This checks repeatability
over minutes; it does not establish stability across days or serving conditions.

The repeated-text fixture varies actual input/cache length. It supports a local
context-length mechanism; testing covert truncation requires identical long
requests and a provider that actually truncates them.

## Model and execution-path timing floor

Source: [clock-floor.json](a100_campaign_20261017/clock-floor.json).
The complete grid covers four model/precision configurations × two execution
paths × six contexts, each at batch 1 with 192 steps × 4 repetitions.
Prefill is outside the timed interval, in chunks of 256 tokens.

| Model and weights | Path | 256-token interval, ms | 32,768-token interval, ms | Difference, ms |
|---|---|---:|---:|---:|
| Qwen3-0.6B BF16 | CUDA graph | 5.756 | 67.683 | 61.927 |
| Qwen3-0.6B BF16 | HF eager | 23.414 | 23.566 | 0.152 |
| Qwen3-1.7B BF16 | CUDA graph | 7.333 | 69.238 | 61.905 |
| Qwen3-1.7B BF16 | HF eager | 23.258 | 23.725 | 0.467 |
| Qwen3-4B BF16 | CUDA graph | 11.998 | 107.413 | 95.414 |
| Qwen3-4B BF16 | HF eager | 30.866 | 33.290 | 2.424 |
| Qwen3-1.7B actual NF4 | CUDA graph | 6.660 | 68.770 | 62.110 |
| Qwen3-1.7B actual NF4 | HF eager | 36.089 | 36.248 | 0.159 |

Timing depends on the execution path. Graph uses a static cache and eager uses
a dynamic cache; attention implementation is not explicitly fixed at model
load. This comparison therefore combines cache, kernel and overhead changes.
The flatter eager curve alone does not establish context truncation. Thresholds
need calibration for the allowed execution setup. Actual NF4 was measured for
timing only; these cells do not measure token-based NF4 detection.

## Scope and next experiments

Together with the [H100 campaign](h100_campaign_20261016.md), this adds a second
hardware baseline. Each host generated and replayed its own token pool. The
campaigns used different code revisions and drivers, so their differences
cannot be attributed solely to GPU SKU or interpreted as paired cross-GPU d′.

The next experiment remains a frozen honest token capture replayed on both
H100 and A100, with aligned model revisions, software and scoring parameters.
Cross-day runs, L40S, independent calibration/test blocks and same-request
token-plus-client-time collection also remain open. This four-task queue did
not run batching, speculative decoding or controlled interference on A100.

## Reproducibility

[provenance.json](a100_campaign_20261017/provenance.json) records source runs,
SHA-256 hashes, settings, model revisions, software and runtime for all six
measurements, plus hashes of the successful and failed queue records/logs.
Result JSON files are byte-for-byte copies; each hardware campaign has its own
archive directory.

Hardware: NVIDIA A100-SXM4-80GB. Software: Python 3.12.3, PyTorch 2.8.0+cu128,
Transformers 4.57.6, bitsandbytes 0.50.2, NumPy 2.1.2, SciPy 1.18.1,
Accelerate 1.15.0 and NVIDIA driver 595.91.07. The driver's reported CUDA
capability is 13.2; PyTorch uses a CUDA 12.8 runtime.

Rebuild and check the numerical summary using only the Python standard library:

```sh
python3 experiments/analyze_a100_campaign.py
python3 experiments/analyze_a100_campaign.py --check
```

The checker validates artifact hashes, queue completion, model references,
baseline grid coverage, timing sample counts/means and token rerun controls.
It preserves the original token bootstrap intervals; the saved results do not
include the per-sequence scores needed to re-estimate them.

For fresh measurements, use a clean checkout at the measurement commit above
and follow the [environment setup](../MULTI_MACHINE_EXPERIMENTS.md). Populate
the pinned model cache first, use offline model loading, and set `MODEL_LOCK`
to a JSON file containing the `models` mapping from provenance. Run serially
on an otherwise idle host:

```sh
for job in clock-window clock-stability token-shape clock-floor; do
  python scripts/run_research_job.py --node a100-80-01 --gpu 0 \
    --job "$job" --size baseline --model-lock "$MODEL_LOCK" || break
done
```
